# Unitree R1 VR Teleoperation in Isaac Sim

Whole-body teleoperation of a simulated **Unitree R1** humanoid with two **BrainCo Revo 2** dexterous hands, controlled from a **Meta Quest 3** through hand tracking. The robot runs in **Isaac Sim 6.1 / Isaac Lab 3.0**, the operator side is Unitree's [xr_teleoperate](https://github.com/unitreerobotics/xr_teleoperate) with patches for the R1 and the BrainCo hands, and a **ROS 2 Humble** workspace is included. Everything runs in Docker.

In the headset you stand in your own room (colour pass-through) with the robot's table and a side table drawn into it. The robot's palms go where your palms are, each finger bends as far as yours, and the body walks, turns, squats and leans with you. The table holds an assembly kit: a peg board, a gear train, a Tower of Hanoi and a nut on a threaded bolt. Sessions can be recorded as demonstrations for imitation learning.

## Features

- Unitree R1 (26 DoF, 5-DoF arms) with two BrainCo Revo 2 hands (6 motors, 11 joints each), composed from Unitree's official URDFs at image build time
- Exact hand mapping: the robot's palm is placed at the operator's palm; direct per-finger mapping
- Whole-body following: the robot's body is placed where the operator stands, with procedural steps; an RL-trained balance controller is available as an alternative
- Lab view rendered in the headset at the operator's scale, with pass-through or a simulated room
- Buttons in VR: START, REC, RESTART, RESET, EXIT
- Grip assist that keeps a grasped part in the closing hand while it still collides
- Assembly kit and a simple pick-and-place scene
- Episode recording in xr_teleoperate's format (head camera, joint states, actions, simulator state)
- Same DDS protocol as the real robot (`rt/lowcmd`, `rt/arm_sdk`, `rt/lowstate`, `rt/brainco/*`), so the teleop and ROS 2 containers work unchanged against the simulator
- GPU-free mock simulator and a simulated headset for automated end-to-end tests

## Architecture

```
 Meta Quest 3 (browser, WebXR head + hand tracking)
        |  https / wss :8012 (same Wi-Fi)
        v
 +---------------------------+     DDS domain 1 on lo        +-------------------------------+
 | teleop (xr_teleoperate)   | -- rt/arm_sdk --------------> | sim (Isaac Sim 6.1 + Lab 3.0) |
 |  televuer web server      | -- rt/sim/body_cmd ---------> |  R1 + 2x BrainCo              |
 |  lab view + VR buttons    | -- rt/brainco/*/cmd --------> |  table, assembly kit          |
 |  R1_A5 arm IK             | <- rt/lowstate, brainco state |  DDS bridge, camera server    |
 |  BrainCo finger mapping   | <- lab poses (ZMQ 55570)      |                               |
 +---------------------------+                               +-------------------------------+
                                  ^ same DDS topics
                                  |
                  +-------------------------------+
                  | ros2 (Humble, rmw_cyclonedds) |  /joint_states, /r1/head_camera/*, RViz
                  +-------------------------------+
```

## Requirements

- Ubuntu 22.04 or 24.04 with an NVIDIA RTX GPU
- NVIDIA driver 595.58.03 or newer (required by Isaac Sim 6.1)
- Docker with the Compose plugin, and the NVIDIA Container Toolkit (installed by `scripts/setup_host.sh`)
- About 60 GB of free disk space for the images
- An NVIDIA NGC account may be needed to pull `nvcr.io/nvidia/isaac-sim:6.1.0`
- Meta Quest 3 on the same Wi-Fi network as the PC, with hand tracking enabled

## Installation

```bash
git clone https://github.com/omkarkorg/unitree_R1_simulation.git
cd unitree_R1_simulation
cp .env.example .env
sudo ./scripts/setup_host.sh
./scripts/gen_certs.sh
./scripts/build.sh
./scripts/check_host.sh
```

`setup_host.sh` installs the NVIDIA Container Toolkit and opens port 8012 for the headset. `gen_certs.sh` creates the self-signed HTTPS certificate WebXR needs and writes the PC's LAN address into `.env`; run it as your normal user. The first `build.sh` pulls Isaac Sim, builds Isaac Lab from a pinned commit and builds the three images (`unitree-r1/sim:6.1.0`, `unitree-r1/teleop:2.3`, `unitree-r1/ros2:humble`); expect 30 to 90 minutes.

All upstream code (Isaac Lab, xr_teleoperate, unitree_sdk2_python, unitree_ros, unitree_ros2, CycloneDDS) is cloned at pinned commits during the build. The R1 + BrainCo model is generated by `tools/build_r1_brainco_model.py`, and the changes to xr_teleoperate are applied from `docker/teleop/patches/`.

## Usage

Terminal 1, the simulator:

```bash
./scripts/run_sim.sh
```

Terminal 2, teleoperation:

```bash
./scripts/run_teleop.sh
```

`run_teleop.sh` renews the certificate if the PC's IP has changed, waits for the simulator and prints the headset address, for example `https://192.168.1.50:8012/?ws=wss://192.168.1.50:8012`. Always use the address it prints.

In the headset:

1. Put the controllers down so the Quest switches to hand tracking.
2. Stand with about 1.5 m free in front of you and on your right.
3. Open the Browser, enter the printed address, then choose Advanced and Proceed to accept the self-signed certificate.
4. Press **Pass-through** (or **Virtual Reality** with `TELEOP_PASSTHROUGH=0`) and allow hand tracking.
5. Press **START** with a fingertip, hold both hands over the table and look at the table during the countdown.
6. At **GO** the robot takes over your pose. Parts lie on the side table to your right.
7. Press **EXIT** twice, or `q` in terminal 2, to stop. Stop the simulator with Ctrl+C.

The robot follows only while both hands are tracked; otherwise it holds and the status board says why. **RESTART** re-aligns the robot to you, **RESET** (twice) puts the parts back.

### Recording demonstrations

```bash
./scripts/run_teleop.sh --record
```

Press **REC** after GO to start an episode and again to save it. Episodes are written to `data/<TELEOP_TASK_NAME>/episode_NNNN/`.

### Other commands

```bash
./scripts/reset_scene.sh
./scripts/reset_scene.sh all
./scripts/run_ros2.sh
./scripts/run_ros2.sh bash
./scripts/run_ros2.sh ros2 run r1_ros2 arm_demo

```

## Configuration

Settings live in `.env`. The most useful ones:

| Variable | Default | Meaning |
|---|---|---|
| `HOST_IP` | set by `gen_certs.sh` | LAN address the headset connects to |
| `SIM_HEADLESS` | `0` | `1` runs Isaac Sim without a window |
| `SIM_SCENE` | `assembly` | `assembly` kit or `pick_place` (cube and cylinder) |
| `SIM_LOCOMOTION` | `1` | `0` fixes the pelvis, arms and hands only |
| `SIM_BODY` | `exact` | `exact` places the body where you are; `balance` uses the trained leg controller |
| `SIM_GRIP_ASSIST` | `1` | keep a grasped part in the closing hand |
| `SIM_STEREO` | `1` | two head cameras for recordings |
| `TELEOP_VIEW` | `lab` | `lab` draws the scene in the headset; `camera` shows the robot's camera image |
| `TELEOP_PASSTHROUGH` | `1` | your real room around the robot; `0` for a simulated room |
| `TELEOP_WORLD_SCALE` | `auto` | draw the robot at your size; `1` for life size |
| `TELEOP_HAND_MAPPING` | `exact` | `exact`, `relative` or `unitree` |
| `TELEOP_FINGER_MAPPING` | `direct` | `direct` or `dexpilot` |
| `TELEOP_WHOLE_BODY` | `1` | `0` keeps the robot standing still |
| `TELEOP_ARM_SPEED_LIMIT` | `10` | arm joint speed limit in rad/s |
| `TELEOP_RECORD` | `1` | allow recording with the REC button |
| `DDS_DOMAIN_ID` | `1` | DDS domain of the simulator |

A variable set on the command line overrides `.env`, for example `SIM_HEADLESS=1 ./scripts/run_sim.sh`.

## Tests

| Command | Needs | Checks |
|---|---|---|
| `./scripts/test_stack.sh` | Docker only | protocol and CRC, camera stream, arm and hand controllers, ROS 2 bridges, and a full xr_teleoperate session driven by a simulated headset against the mock simulator |
| `./scripts/test_stack.sh --isaac` | `run_sim.sh` running | the same against Isaac Sim, plus the leg controller and following precision |
| `./scripts/test_pick.sh` | `run_sim.sh` running | picks every kit part off the side table and carries it |
| `./scripts/test_assembly.sh` | GPU | physics of the assembly kit |
| `./scripts/grasp_test.sh` | `run_sim.sh` with `SIM_SCENE=pick_place SIM_LOCOMOTION=0` | scripted pick |

Do not run the tests while your own simulator or teleop session is active; they share the DDS domain and ports.

## Leg controller training

The balance controller used with `SIM_BODY=balance` is trained with Isaac Lab and RSL-RL. The exported policy is included at `r1_sim/policies/r1_wholebody.pt`.

```bash
./scripts/train_loco.sh
./scripts/train_loco.sh --export
./scripts/train_loco.sh --evaluate
```

Checkpoints are written to `logs/rsl_rl/r1_wholebody/`.

## Real robot

The teleop and ROS 2 containers speak the robot's DDS protocol. For the real R1, set `DDS_DOMAIN_ID=0` and `DDS_INTERFACE` to the robot network interface, run Unitree's teleimager on the robot, use `TELEOP_VIEW=camera`, and start xr_teleoperate without `--sim`. Whole-body following depends on the simulator and is not available on the real robot. This has not been tested on hardware. Follow Unitree's safety instructions for low-level control.
